# Заметки разработчика / Developer notes

Этот файл — для того, кто будет дорабатывать программу.
Здесь то, чего нет в коде: **почему** всё устроено именно так, проверенные факты о BSGO Nova и Запрете,
найденные ошибки и как проверять изменения. Прочитайте его целиком перед правками.

---

## 1. Устройство

| Файл | Что делает |
|---|---|
| `src/BSGO_Tester.ahk` | Главное окно, шаги 1–3, запрос прав администратора, аварийное восстановление при запуске |
| `src/lib/i18n.ahk` | Все тексты RU/EN: `T("ключ")`, определения `S("ключ", ru, en)` |

| `src/lib/zapret.ahk` | Папка Запрета, служба `zapret`, `winws.exe`, Game Filter, сохранение и восстановление состояния |

(файлы восстановления Запрета на время проверки). Они в `.gitignore` — это личные данные.

## 2. Сборка и проверка изменений

- Нужен **AutoHotkey v2 (64-бит)** с компилятором Ahk2Exe. Сборка: `build.bat` → `build\BSGO_Tester.exe`.
- Проверка синтаксиса после каждой правки:
  `"\AutoHotkey\v2\AutoHotkey64.exe" /ErrorStdOut=UTF-8 /validate src\BSGO_Tester.ahk`
- Файлы `.ahk` — **UTF-8 с BOM и CRLF** (`.gitattributes` следит за CRLF).
- `/validate` НЕ ловит ошибки, которые всплывают только при выполнении (см. §6). Дополнительно проверять:
  - нет переменных, чьё имя совпадает с именем функции (без учёта регистра);
  - нет ключа `base:` в объектных литералах;
  - каждый `T("ключ")` определён в `i18n.ahk`.
- Итоговая проверка — только на живой игре: шаги 1 → 2 (можно выбрать 1–2 стратегии) → 3 до входа в мир.
  Шаг 3 и всё, что трогает Запрет, требуют прав администратора — их запускает человек.

## 3. Проверенные факты (октябрь 2026)

### BSGO Nova
- Сайт/API: `playbsgo.com`; игровой сервер — по имени `game.playbsgo.com` (лаунчер 1.0.81 ищет сервер по имени).
  IP на 10.2026: **37.187.145.5** (OVH, Гравлин). Однажды DoH Cloudflare вернул 54.215.31.113 — не воспроизвелось.
- Лаунчер: `BSGO Launcher.exe`, **Electron 31 / Node 20**, стандартный путь `\bsgo nova\BSGO Launcher\`.
  Фид обновлений: `https://playbsgo.com/download/latest.yml` (поле `path:` — имя установщика, ~81 МБ).
- Вход в аккаунт: появляется `%APPDATA%\bsgo-launcher\bsgo_session_token`, удаляется при закрытии лаунчера.
  **Содержимое не читаем никогда** — только факт/время изменения.
- Проверка файлов: лаунчер читает ~1 ГБ с диска за несколько секунд после входа и ещё раз при «Играть».
  Список файлов: запрос `GET /launcher/manifest` (тайм-аут лаунчера 20 с).
- Игра: `client\live\bsgo.exe` (Unity 5.1.5), лог `client\live\bsgo_Data\output_log.txt` — **перезаписывается
  при каждом запуске**. Маркеры: `Game.Me.ServerID` (сервер принял вход), `Loading player ship`,
  `PlayerShip.OnRead IsMe-true`, **`has made it into the game`** = вход в мир (настраивается: `[game] world_marker`).
- Игровые порты TCP: **27050** (до ServerID), **9338** (перед загрузкой сцены). В командной строке `bsgo.exe`
  лаунчер передаёт только IP, без портов — порты выучиваются по реальным соединениям.
- Соединения игры с 34.111.113.40 / 34.107.172.168 :443 — короткие при старте, назначение неизвестно.
  178.132.246.28 = `eventstream-…bigpoint.net` (телеметрия) — его ошибки безвредны.

### Проблема у игроков из России
- Без обхода: TCP и TLS проходят, но **любой ответ сервера обрывается на ~15 КБ** (15318–15370 байт).
  Лаунчер не получает manifest → «не удалось проверить целостность игры: request timed out after 20000ms».
  Соединения висят в FIN_WAIT1 — пакеты теряются на маршруте. Кто это делает — не доказано.
- Администрация сама советует игрокам из РФ VPN с полным туннелем; также жалобы на отключение через ~2 мин.

### Запрет (Flowseal zapret-discord-youtube 1.10.3)
- Стратегии — `general*.bat` в корне; `service.bat` (служба `zapret`), `bin\winws.exe` (zapret v72.x), `lists\`.
- Game Filter: `utils\game_filter.enabled` (`mode=disabled|tcp|udp|all`, `tcp=1024-65535`).
  При выключенном фильтре `%GameFilterTCP%` = **12** (фиктивный порт).
- `ipset-all.txt` содержит 37.187.0.0/16; `playbsgo.com` у автора есть в `list-general-user.txt`.
- `service.bat check_updates` срабатывает, только если есть `utils\check_updates.enabled`.

## 4. Как устроены проверки и почему

- **Главный судья уровня лаунчера — «движок лаунчера»**: сам `BSGO Launcher.exe` с `ELECTRON_RUN_AS_NODE=1`
  выполняет JS (`https.get`, первые 2 МБ установщика, Range, 3 попытки, стоп при 6 с без данных).
  Почему: curl (Schannel) у части игроков не работает вовсе (полевой тест), а иногда проходит там, где
  лаунчер падает (ALT10, SIMPLE FAKE ALT). Самопроверка `LauncherEngineSelfTest()`: если режим Node отключат
  в новой версии лаунчера, вместо проверки откроется обычный лаунчер — ждём 10 с и закрываем, дальше curl.
- **curl** (`System32\curl.exe`) — запасной/информационный. Всегда `--noproxy "*" --ssl-no-revoke`.
  Самопроверка — чтение `file:///…/win.ini`. Режим `telnet://` НЕ использовать (зависает на чтении stdin).
- **Chromium** (статус «Соединено»): Edge `--headless=new --dump-dom` главной страницы; признак полной страницы —
  `<footer` (начинается после ~15,6 КБ). Edge от администратора не работает → запуск через `ShellRun`
  (оболочка Explorer, без прав); **на каждую попытку новый `--user-data-dir`**, иначе новый Edge отдаёт адрес
  уже запущенному и ничего не выводит. Самопроверка на локальной странице. Если Chromium проваливается у всех
  стратегий, где лаунчер прошёл, — считаем, что изменился сайт, и не учитываем его.
- **DNS**: системный (`DnsQuery_W`) и DoH через JSON (`cloudflare-dns.com`, `dns.google`) — режим curl
  `--doh-url` на Windows не работает.
- **TCP к игровым портам** — неблокирующий `connect` + `select` (winsock), без отправки данных.
- **Классы шага 2**: A — кандидат (лаунчер ок, порты открыты, стратегия обрабатывает порты в `.bat`),
  B — только лаунчер, E — нестабильно (часть попыток), C — не проходит, D — не запустилась.
  Умный режим: только Game Filter TCP, стоп после 3 кандидатов. Сортировка стратегий — `Sort(…, "CLogical")`.
- **Что НЕ предсказывается по сети**: войдёт ли игра в мир. EXP и ALT13 с GF TCP проходят отсев, но виснут
  в игре. Поэтому шаг 3 обязателен.
- **Узкая стратегия**: берётся правило `--filter-tcp=%GameFilterTCP%` **той же** стратегии (она только что
  прошла в игре с GF TCP), порты → выученные, `--ipset` → `lists\ipset-bsgo-tester.txt` (выученный IP),
  порты добавляются в `--wf-tcp`. Файл `… - BSGO narrow.bat`, исключается из сканирования (`[scan] exclude`).
- **Предел длины команды cmd (8191 символ после подстановки путей)** — главная ловушка генератора: при длинном
  пути к Запрету строка не влезает, команда рвётся (`'--filter-udp' is not recognized`). Генератор проверяет
  результат `winws --dry-run` **той же строкой, что при запуске** (`start "<заголовок>" /b /wait …`, самые
  длинные значения Game Filter) и при нужде сокращает: 1) без `--ipset-exclude` в новом правиле,
  2) без исходного правила GF. Если узкая версия не запустилась/не вошла в мир на шаге 3 — файл удаляется.
- **Самопроверка переезда сервера** при запуске: IP в `ipset-bsgo-tester.txt` сравнивается с DNS
  `game.playbsgo.com`; если отличается — предлагается переписать список (сам `.bat` трогать не нужно).

## 5. Безопасность и приватность (не нарушать)

- Не читать пароли, токены, содержимое `bsgo_session_token`; из командной строки игры брать только `IP[:порт]`.
- Перед любым изменением Запрета — `SaveZapretState()`; `OnExit(EmergencyRestore)`; при запуске программы —
  восстановление, если осталось `restore\state.txt`.
- Копии лога игры содержат имя персонажа — не публиковать.
